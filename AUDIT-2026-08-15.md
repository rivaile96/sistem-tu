# AUDIT LAPORAN — sistem-tu
**Tanggal:** 2026-08-15  
**Auditor:** Kiro (subagent)  
**Environment:** Production (`APP_ENV=production`, `APP_DEBUG=false`)  
**URL:** https://tu.brody.my.id  
**Stack:** Laravel 11, MariaDB, Vite + Tailwind CSS v3 + Alpine.js, Midtrans, Sanctum API

---

## TEMUAN KRITIS (harus difix segera)

---

### [KRITIS-1] `BillItem`, `PosBundle`, `PosBundleItem`, `PosItem` — `$guarded = []` (unguarded)

**File:**
- `app/Models/BillItem.php` — `protected $guarded = [];`
- `app/Models/PosBundle.php` — `protected $guarded = [];`
- `app/Models/PosBundleItem.php` — `protected $guarded = [];`
- `app/Models/PosItem.php` — `protected $guarded = [];`

**Masalah:** `$guarded = []` berarti **semua kolom bisa diisi via mass assignment** — termasuk `id`, foreign key sembarangan, field audit/sensitif. Ini adalah posture paling lemah yang ada di Eloquent.

**Dampak:** Jika ada path di controller yang melewatkan `$request->all()` atau `$request->validated()` ke `create()`/`update()`, attacker bisa inject kolom apapun — termasuk `id`, relasi foreign key, atau field privilege.

**Konfirmasi:** `PosItemController` terbukti menggunakan `$request->all()` langsung:
```php
// PosItemController
$data = $request->all();          // line 32 (store)
$data = $request->all();          // line 54 (update)
$item->update($data);             // line 65
```
Ini adalah **mass assignment exploitation yang confirmed** — tidak ada filter, semua field dari request langsung masuk ke DB.

**Fix yang dibutuhkan:** Ganti ke `$guarded = ['id']` atau definisikan `$fillable` eksplisit pada semua model di atas. Fix `PosItemController` untuk tidak menggunakan `$request->all()` langsung.

---

### [KRITIS-2] `PosItemController` — `$request->all()` langsung ke `update()`

**File:** `app/Http/Controllers/PosItemController.php`

**Masalah:**
```php
$data = $request->all();   // tanpa filter
$item->update($data);      // semua field dari request langsung masuk DB
```
Karena `PosItem` punya `$guarded = []`, ini berarti attacker yang authenticated bisa kirim field apapun (termasuk `id`, `created_at`, relasi) dan akan tersimpan ke DB.

**Fix:** Ganti dengan `$request->only([...])` atau buat `FormRequest` dengan field yang diizinkan secara eksplisit.

---

### [KRITIS-3] CSP (Content Security Policy) — Dimatikan total

**File:** `app/Http/Middleware/ContentSecurityPolicy.php`

**Masalah:**
```php
/**
 * Middleware CSP DIMATIKAN TOTAL
 * Biar dashboard, chart, JS, dan Midtrans aman
 */
public function handle(Request $request, Closure $next): Response
{
    return $next($request);  // tidak melakukan apapun
}
```
CSP dimatikan total dengan komentar eksplisit. Aplikasi tidak punya perlindungan terhadap XSS via Content-Security-Policy header sama sekali.

**Dampak:** Jika ada XSS vulnerability (lihat MEDIUM-3), tidak ada layer defense-in-depth yang mencegah script injection dari sumber eksternal.

**Catatan:** Alasan "biar Midtrans aman" tidak valid — CSP bisa dikonfigurasi untuk whitelist domain Midtrans (`*.midtrans.com`). CDN SweetAlert2 dari jsdelivr juga bisa di-whitelist.

---

### [KRITIS-4] Register route publik — siapapun bisa daftar akun

**File:** `routes/auth.php`

**Masalah:**
```php
Route::get('register', [RegisteredUserController::class, 'create'])->name('register');
Route::post('register', [RegisteredUserController::class, 'store']);
```
Route registrasi tidak dilindungi middleware apapun — tidak ada `auth`, tidak ada `admin`, tidak ada invite token. Siapapun yang tahu URL `/register` bisa membuat akun baru di sistem sekolah.

**Dampak:** Karena tidak ada role/permission system (lihat MEDIUM-1), akun baru yang dibuat langsung punya akses ke seluruh fitur admin (dashboard, data siswa, keuangan, POS).

**Fix:** Nonaktifkan route register publik, atau proteksi dengan middleware `auth` + cek role admin, atau hapus sama sekali dan buat user management di panel admin.

---

### [KRITIS-5] Tidak ada rate limiting pada API login

**File:** `routes/api.php`

**Masalah:**
```php
Route::post('/login', [ParentApiController::class, 'login']);  // publik, tidak ada throttle
```
API login untuk mobile app (ParentApiController) tidak punya rate limiting. Web login Laravel 11 memiliki throttle default `throttle:login`, tapi API endpoint ini adalah custom route yang tidak mewarisi throttle tersebut.

**Dampak:** Brute-force attack pada password akun orang tua tidak ada throttle-nya.

**Fix:** Tambahkan `middleware('throttle:5,1')` (5 request per menit) pada route login API.

## TEMUAN MEDIUM (perlu difix)

---

### [MEDIUM-1] Tidak ada role/permission system

**Masalah:** Tidak ada package `spatie/laravel-permission` atau role system apapun yang terdeteksi. Semua user yang authenticated memiliki akses ke semua route web (`middleware('auth')`).

**Dampak:**
- Akun orang tua (dari API) yang jika secara tidak sengaja bisa mengakses web, akan punya akses penuh
- Tidak ada segregasi admin vs staff vs viewer
- Jika register publik tidak ditutup (KRITIS-4), akun baru langsung jadi super-admin de facto

**Fix:** Implementasi minimal role system — setidaknya flag `is_admin` pada tabel `users`, atau integrasi Spatie Permission.

---

### [MEDIUM-2] `SchoolSettingController@update` — arbitrary key/value injection ke DB

**File:** `app/Http/Controllers/SchoolSettingController.php`

**Masalah:**
```php
$data = $request->except(['_token', 'school_logo', 'school_signature']);

foreach ($data as $key => $value) {
    DB::table('school_settings')->updateOrInsert(
        ['key' => $key],
        ['value' => $value, 'updated_at' => now()]
    );
}
```
Semua field dari request (kecuali token dan file) langsung di-`updateOrInsert` ke tabel `school_settings`. Seorang attacker yang authenticated bisa menambahkan key sembarangan atau mengubah key yang tidak seharusnya bisa diubah via form (misalnya key internal yang digunakan sistem).

**Fix:** Whitelist key yang diizinkan secara eksplisit:
```php
$allowedKeys = ['school_name', 'school_address', 'school_phone', 'treasurer_name'];
$data = $request->only($allowedKeys);
```

### [MEDIUM-3] SweetAlert2 dimuat dari CDN (external script)

**File:** `resources/views/layouts/app.blade.php`

**Masalah:**
```html
<script src="https://cdn.jsdelivr.net/npm/sweetalert2@11"></script>
```
SweetAlert2 dimuat dari CDN eksternal tanpa `integrity` attribute (Subresource Integrity / SRI). Jika CDN dikompromikan, script berbahaya bisa dieksekusi di semua halaman aplikasi.

Ini juga alasan sebenarnya kenapa CSP dimatikan total — dengan CSP aktif, script CDN ini akan diblokir kecuali di-whitelist.

**Fix opsi 1 (preferred):** Bundle SweetAlert2 via npm (sudah tersedia dalam `package.json` jika belum) dan import via Vite.  
**Fix opsi 2:** Tambahkan SRI hash: `<script src="..." integrity="sha384-..." crossorigin="anonymous">`.

---

### [MEDIUM-4] `layouts/app.blade.php` menggunakan `{{ $slot }}` bukan `@yield`

**File:** `resources/views/layouts/app.blade.php` (line 206)

**Masalah:** Layout utama menggunakan `{{ $slot }}` (Blade component slot syntax), tapi beberapa view menggunakan `@extends('layouts.app')` + `@section('content')`:

Views yang menggunakan `@extends('layouts.app')` (template inheritance lama):
- `resources/views/rombel/edit.blade.php`
- `resources/views/rombel/show.blade.php`
- `resources/views/rombel/create.blade.php`
- `resources/views/rombel/index.blade.php`
- `resources/views/rombel/tahun-ajaran/index.blade.php`
- `resources/views/rombel/tahun-ajaran/create.blade.php`
- `resources/views/rombel/tahun-ajaran/edit.blade.php`

**Dampak:** View-view rombel akan **dirender tanpa layout** — tidak ada sidebar, tidak ada navbar, konten tampil polos atau blank karena `@section('content')` tidak pernah di-yield oleh layout yang menggunakan `{{ $slot }}`.

**Catatan penting:** `AppLayout` component (`app/View/Components/AppLayout.php`) me-render `layouts.app` — jadi `<x-app-layout>` dan `@extends('layouts.app')` sebenarnya merujuk ke file yang SAMA. Masalahnya adalah satu memakai slot, satu memakai yield. Solusinya: tambahkan `@yield('content')` di dalam `layouts/app.blade.php`, atau konversi semua rombel views ke `<x-app-layout>`.

### [MEDIUM-5] `rombel/show.blade.php` — `$siswa->nama` tapi Student model punya field `name` bukan `nama`

**File:** `resources/views/rombel/show.blade.php` (line 197)

**Masalah:**
```blade
{{ $siswa->nama }}         {{-- line 197: akses ke kolom 'nama' --}}
{{ $sr->student->nama }}   {{-- line 118: akses via relasi --}}
```
Student model menggunakan kolom `name` (standard Laravel) bukan `nama`. Referensi `->nama` akan return `null` secara diam-diam (tidak error, karena Eloquent), tapi data nama siswa tidak akan tampil.

**Konfirmasi:** `RombelController@show` mengirim `$siswaBelumRombel` (collection of Students) tapi tidak ada `$siswa->nama` yang valid jika kolom namanya `name`.

**Perlu dicek:** apakah di `students` table kolom bernama `name` atau `nama` — ini menentukan mana yang salah.

### [MEDIUM-6] API Midtrans callback tidak diproteksi oleh signature validation yang ketat

**File:** `routes/api.php`

**Masalah:**
```php
Route::post('/midtrans-callback', [ParentApiController::class, 'callback']);
```
Endpoint ini publik (seperti seharusnya untuk webhook). Tapi perlu dipastikan validasi signature Midtrans dilakukan dengan benar — yaitu memverifikasi `signature_key` dari payload menggunakan `SHA512(order_id + status_code + gross_amount + ServerKey)`.

**Status:** Komentar di kode menyebut "signature validation is present" tapi implementasi lengkapnya perlu diverifikasi secara terpisah.

---

### [MEDIUM-7] `PosItemController` store dan update — tidak ada validasi input

**File:** `app/Http/Controllers/PosItemController.php`

**Masalah:** Store dan update menggunakan `$request->all()` langsung tanpa `$request->validate()`. Tidak ada validasi tipe data, panjang string, atau keberadaan field wajib.

**Dampak:** Data tidak valid bisa masuk ke DB (string di field numerik, dll) yang bisa menyebabkan error downstream saat kalkulasi.

---

### [MEDIUM-8] `PPDBController@store` — field `nis` dan `class_name` tidak dikirim ke `Student::create()`

**File:** `app/Http/Controllers/PPDBController.php`

**Status setelah investigasi:** TIDAK lagi kritis — dua migrasi terbaru (`2026_08_14_183035` dan `2026_08_14_183140`) telah mengubah kolom `nis` dan `class_name` menjadi `nullable`. Jadi `Student::create()` tanpa kedua field ini tidak akan menyebabkan SQL error lagi.

**Namun masih ada catatan:**
- PPDBController@store tidak mengirim `nis` dan `class_name` ke Student baru, tapi field `nis` di form PPDB dan validasi controller tidak menyertakan field ini — desain ini sepertinya intentional (siswa PPDB belum punya NIS)
- Perlu dipastikan ada workflow setelah PPDB untuk mengisi `nis` dan `class_name` setelah siswa diterima (lihat `StudentController@update` sudah handle ini)

## TEMUAN MINOR (nice to have)

---

### [MINOR-1] Dua sistem billing berjalan paralel tanpa integrasi

**Masalah:** Ada dua model billing terpisah:
- `StudentBill` + `BillItem` — sistem tagihan modern (SPP, iuran, dll)
- `SppBill` — model legacy untuk SPP

`SppController` menggunakan `SppBill`, sementara `BillController` menggunakan `StudentBill`. Tidak ada relasi atau sinkronisasi antara keduanya.

**Dampak:** Data keuangan bisa tidak konsisten. Laporan dari dua sumber berbeda.

---

### [MINOR-2] Google Fonts dimuat dari CDN eksternal

**File:** `resources/views/layouts/app.blade.php`

**Masalah:**
```html
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@300;400;500;600;700&display=swap" rel="stylesheet">
```
Ketergantungan pada Google Fonts CDN berarti font tidak dimuat jika pengguna tidak ada koneksi ke Google (beberapa sekolah punya filter DNS). Lebih baik self-host font via `fontsource` package.

---

### [MINOR-3] `AuditLog` model tidak digunakan secara konsisten

**File:** `app/Models/AuditLog.php`

**Masalah:** Model `AuditLog` ada tapi tidak ada Observer atau trait yang memanggil pencatatan audit secara otomatis. Audit logging hanya dilakukan secara manual di beberapa controller, bukan semua operasi kritis.

---

### [MINOR-4] Queue tidak digunakan — operasi berat berjalan synchronous

**File:** `.env`

```
QUEUE_CONNECTION=sync
```
Semua job (email notifikasi, proses pembayaran, dll) berjalan synchronous. Di sekolah dengan ratusan siswa, operasi bulk (naik kelas, generate tagihan masal) bisa timeout.

---

### [MINOR-5] Session driver `file` — tidak scalable

**File:** `.env`

```
SESSION_DRIVER=file
SESSION_DRIVER=file
CACHE_STORE=file
```
Cocok untuk single server. Tapi jika load balancer atau multiple instance ditambahkan di masa depan, session akan invalid. Pertimbangkan Redis atau database driver.

---

### [MINOR-6] `APP_KEY` dan secrets tidak ada di audit scope

Tidak membaca nilai dari `.env` untuk menjaga kerahasiaan. Perlu dipastikan secara terpisah:
- `APP_KEY` sudah di-generate dan bukan placeholder
- `MIDTRANS_SERVER_KEY` dan `MIDTRANS_CLIENT_KEY` sudah diisi
- `APP_KEY` tidak pernah di-commit ke git

---

### [MINOR-7] `NaikKelasController` — potensi operasi besar tanpa konfirmasi

**Masalah:** Fitur naik kelas memindahkan semua siswa ke kelas berikutnya. Tidak ada preview jumlah siswa yang akan terpengaruh sebelum eksekusi, tidak ada fitur rollback/undo.
